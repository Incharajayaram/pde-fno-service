Resolution invariance check

This model was trained at 128×128. PDEBench's Darcy Flow data is natively 128×128 too — unlike the 1D Burgers' dataset (native 1024, trained at 256), there's no independent higher-resolution ground truth available to test true zero-shot super-resolution here. What is verifiable: the same architectural property (spectral convolutions truncated to a fixed 12×12 Fourier modes, independent of grid size) means the exact same trained weights can also run directly at lower resolutions, with no retraining. Below, the held-out test set (1,000 samples) is evaluated at 128/64/32, built by exact striding (no interpolation) of the native field, against real ground truth at each matching resolution.

Resolutionvs. training resolutionRelative L2
128×128training resolution0.043435
64×642× zero-shot coarsening0.068109
32×324× zero-shot coarsening0.161304

Unlike the Burgers model (near-flat error across 4× the training resolution), error here rises substantially at coarser grids. The likely reason: Burgers' viscosity (ν=0.01) smooths its solutions into genuinely band-limited (low-mode) functions, so a 16-mode truncation barely loses anything at any resolution. Darcy's permeability field is binary/piecewise-constant with sharp interfaces — real high-frequency content that exact-stride decimation of the grid itself distorts, independent of the model. This is a genuine limit of resolution-invariance for inputs that aren't smooth, not a bug. Reproducible via python -m src.eval_superres_darcy.
